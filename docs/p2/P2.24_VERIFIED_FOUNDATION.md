# P2.24 — Verified Aurora Partner Foundation (checkpoint)

**Status:** Verified foundation checkpoint — **NOT** complete P2.24.
**Target:** Public WSO2 Identity Server 7.3.0 GA on localhost:9444, Aurora tenant (`aurora.identity.test`). No deployment upgrade.

## Verified live behavior

- Aurora partner organization exists, is active, and is rooted under Aurora; Carbon Super and Brisa remain separate.
- The `P2 Aurora Returns Partner Business Portal` application is mapped to exactly that partner in both sharing API readbacks; role sharing is explicitly `NONE`. The GA API does not return a `sharingMode.policy` value, so this checkpoint does **not** claim direct GET verification of that field.
- The separate `P2 Aurora Returns Partner Directory M2M` is a confidential, partner-shared management client, with the supported **five** organization SCIM scopes: `internal_org_user_mgt_create`, `internal_org_user_mgt_list`, `internal_org_user_mgt_view`, `internal_org_group_mgt_create`, and `internal_org_group_mgt_view`. `internal_org_group_mgt_list` is not in the deployed catalog.
- Two **disabled** partner users exist without assigned roles: `p2-aurora-returns-operator` and `p2-aurora-returns-reviewer`.
- Two groups, `AuroraReturnsOperators` and `AuroraReturnsReviewers`, each contain exactly their corresponding seeded user.
- Independent live verification (`P2_24_PARTNER_DIRECTORY_LIVE_READBACK_VERIFIED`) confirmed both users, both groups, exact membership, partner-bound token claim and scopes, exclusive M2M sharing, and read-only verification behavior.
- A separate readiness audit (`P2_24_DELEGATED_ADMIN_READINESS_RECORDED`) confirmed the directory **M2M** token received HTTP **403** on root-tenant SCIM Users and root organization-management GET controls. This is **not** proof of human administrator or cross-partner mutation isolation.

## Re-run read-only evidence

From the repository root, with the original private runtime records available **outside Git**:

```bash
python3 scripts/p2/p2_24_checkpoint/verify.py audit
python3 scripts/p2/p2_24_checkpoint/readiness.py audit
python3 -m unittest discover -s tests/p2 -p 'test_p2_24_checkpoint_*.py'
```

The OAuth token exchange uses the `client_credentials` grant to obtain a short-lived token. The verifier itself performs no WSO2 **management or SCIM mutation**. Runtime journals and secrets must remain private and must never be committed.
